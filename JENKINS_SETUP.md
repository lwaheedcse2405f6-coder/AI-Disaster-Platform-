# Jenkins setup for dashboard and changes

The Jenkinsfile prints two useful sections in **Console Output**:

- `SOURCE CHANGE REPORT` lists the current Git commit and files changed since the previous commit.
- `AI DISASTER PLATFORM DASHBOARD` confirms the build and shows live metrics from the backend API.

The Jenkins **Changes** page is generated by Jenkins itself. It cannot show changes when the job reads a Jenkinsfile from a local folder without Git history.

## One-time setup

1. Put this project in a Git repository and push it to GitHub, GitLab, or another Git server.
2. In Jenkins, open the job and select **Configure**.
3. Under **Pipeline**, set **Definition** to **Pipeline script from SCM**.
4. Select **Git**, paste the repository URL, and add credentials if the repository is private.
5. Set **Script Path** to `Jenkinsfile`, then save.
6. Run one successful build to establish a baseline.

## Showing changes during your demo

1. Edit a project file, such as `frontend/src/App.jsx` or `backend/app/services.py`.
2. Commit and push the change.
3. Run the Jenkins job again, or let its repository trigger run it.
4. Open that build's **Changes** link to see the commit and changed files.
5. Open **Console Output** to show the source-change report and the application dashboard.

The first build after enabling SCM can still say `No changes` because Jenkins has no earlier successful build to compare. The next build after a new commit will have a change entry.

## Important note

This Jenkinsfile uses port `18000` only for the short smoke test. That avoids the existing development backend on port `8000`, which caused the previous `WinError 10048` failure in `backend-jenkins-err.log`.
